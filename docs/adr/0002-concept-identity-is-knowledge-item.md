# ADR-0002: 概念同一性以资源内 KnowledgeItem 为边界，MVP 不跨资源归并

- 状态：已接受
- 日期：2026-06-12

## 背景

考核循环以"薄弱概念"为货币：优先出题、答对销账。同一知识点（如 useEffect 闭包陷阱）
可能出现在多个已入库资源中，必须决定概念同一性的边界——它决定 Learning Memory 的
记账粒度、选题的确定性与 eval 的可断言性。

## 决策

概念同一性 = KnowledgeItem（深读单个资源产出的最小知识单元，资源内唯一）。
薄弱概念锚定具体 item id；出题、判卷、销账都引用 item id。跨资源不归并；
接口预留 `concept_key` 字段，二期以别名表 / 聚类做跨资源归并。

## 备选方案

- **全局概念表**：概念为一等实体，LLM 跨资源判同归并，KnowledgeItem 退为证据。
  选题更聪明（一个薄弱点聚合所有证据），但判同不稳定会污染记忆——销错账比重复考
  更伤信任，且归并结果在 replay 下难以确定化。
- **不建概念实体**：薄弱点就是错题记录，出题时喂近期错题上下文给 LLM 自由发挥。
  最省事，但"薄弱优先"成为不可断言的黑盒，违背"可评测"的立项根基。

## 后果

- 出题 / 判卷 / 销账全链路可追溯，grounding 与 eval 断言天然成立。
- 同一知识点跨资源重复为多个薄弱点；N=1 用户量下密度可接受，是有意取舍。
- 二期归并需要数据迁移路径（item id → concept_key 映射），预留字段即为此服务。
