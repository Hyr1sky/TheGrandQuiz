# ADR-0016: Provider fallback 只在显式授权候选间发生

- 状态：已接受
- 日期：2026-09-07

## 背景

ADR-0013～0015 已把用途、部署配置、能力门、Adapter 错误与应用重试拆开。单模型临时不可用时，继续在
同一部署重试并不总是最佳恢复；但“发现机器上还有 key 就换厂商”会越过数据发送授权，显式模型 pin 也会
失去意义。若每个候选重新获得 3 次请求和 90 秒期限，两个模型会把承诺的上限偷偷扩大一倍。

流式与工具调用还要求更严格的边界：已交付前缀后重发可能拼接两个不同答案；已经执行的工具、审批或整个
workflow 不能因模型故障被再次运行。没有收到响应也不能证明远端未处理或未计费。

## 决策

1. fallback 默认关闭，只使用配置或一次 `ModelSelection` 显式给出的有序 Profile 候选；已配置凭证、模型
   目录或环境变量不构成授权。只 pin 一个模型时没有候选链。
2. 配置解析冻结候选顺序并拒绝缺失、重复、回环和指向相同部署指纹的别名。候选顺序、fallback policy 与
   retry policy 进入共同策略身份，运行开始后不随设置变化。
3. 主备候选必须通过请求能力、上下文/输出容量、排除部署身份与实际 stream/tool 资格。备用容量不得低于
   主模型；不以删 Evidence、截断材料或移除请求特性换取资格。
4. 仅 retryable 的 rate limit、timeout、connection 与 server error 可切换。鉴权、权限、坏请求、模型
   不存在、永久额度、冲突、拒绝/安全阻断与 unknown 默认停止。
5. 同一 Logical Call 的 retry 与 fallback 共用 ADR-0015 的全局 attempt、deadline 与累计等待预算；
   `max_attempts_per_candidate` 只缩小单候选份额，不能扩大总预算。
6. fallback 只重发当前模型请求。任意上游 stream event、已交付文本、`replay_safe=false`、取消或未知异常
   都立即停止；Runtime 不重跑已完成工具、审批、状态机或 workflow。
7. `model.fallback_decided` 进入 AgentEvent 脊柱；Attempt 记录实际脱敏身份，逻辑终态记录实际 selected
   identity、切换次数和有序安全失败链。公共投影只显示候选序号、有限原因和身份指纹。
8. Model cassette 按每个候选身份保存 typed outcome；Replay 使用冻结候选与策略身份，不重新执行在线发现、
   健康判断或随机路由。

## 备选方案

- 任意已配置模型自动接管：恢复率可能更高，但数据授权、成本、隐私和 pin 语义都不可解释。
- 每个候选独立重试预算：实现简单，却让总请求次数与延迟随候选数量相乘。
- 收到部分流后换模型续写：无法证明语义连续，会把两个生成过程伪装成一个结果。
- fallback 整个 workflow：可能重复工具副作用和审批，超出模型请求恢复的事务边界。

## 后果

模型可用性恢复现在是有限、可审计且不越权的；用户可以区分同模型 retry 与跨候选 fallback，并看到最终
实际部署身份。代价是运维者必须声明容量和候选授权，且首版宁可失败也不处理部分流、stateful continuation
或未知副作用。该机制不是远端幂等保证：它只约束本地再次发请求的条件与次数，无法保证零重复计费。

本决策不包含质量路由、hedging、熔断、健康探测、动态价格选择、新 wire API 或跨工具事务恢复。
