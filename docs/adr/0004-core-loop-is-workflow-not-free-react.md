# ADR-0004: 核心考核循环是确定性 workflow，自由 ReAct 只用于开放编排

- 状态：已接受
- 日期：2026-06-13

## 背景

项目立项的根基是"可观测、可恢复、可评测"。一个"学习数字人 agent"最直觉的实现是把整个
交互做成自由 ReAct 循环——让 LLM 自主决定每一步。但自由 agency 的路径难以复现、难以断言，
直接侵蚀"可评测 / 可恢复"。考核循环（选题 → 出题 → 答 → 判卷 → 状态转移 → 下一题）恰恰是
最该被 eval 守住的路径。

## 决策

把值得 eval 的核心路径做成**确定性 workflow，LLM 只嵌在有界的槽里**：

- **LLM 负责语义判断**：生成一道带证据的题、判一道题（对 / 勉强 / 错）。均为带 pydantic
  schema 的工具调用。
- **代码负责记账与编排**：薄弱概念状态机转移、Learning Memory 写入、选题候选集构造（薄弱优先），
  全部确定性。
- **保留的 LLM 自主**：候选集内选哪道题交给 LLM——候选集已按薄弱优先构造，最终挑选的自由
  不破坏 weak-first 不变量。
- **自由 ReAct 仅用于开放式编排**：用户随口提问、agent 决定是否深读 / 列资源 / 进入考核。

配套：subagent 判据硬化为"隔离大上下文 + 输出可结构化验证"，MVP 唯一 subagent 是 Reader；
出题 / 判卷是工具。

## 备选方案

- **全自由 ReAct**：整个考核交给 LLM 自主驱动。最灵活，但状态转移 / 选题 / 记忆写入都成黑盒，
  eval case 4/5/6 无法在 trace 上断言，replay 对不齐——与立项根基冲突。
- **全确定性（连判卷也用规则）**：彻底可复现，但判卷退化为关键词匹配，丧失"拷问 + 追问"的
  语义价值。

## 后果

- eval case 4/5/6 可在 trace 上确定性断言；replay 完整。
- 简历叙事更硬：核心路径是"可确定性回放的 workflow，LLM 在两个验证过的槽里"，强于"多智能体编排"。
- 代价：选题保留的 LLM 自主使 case 5 只能断言"选自薄弱优先候选集"而非"选了最薄弱的一个"——
  优先级靠候选集构造（代码）保住，可接受。
- 与 [ADR-0002] / [ADR-0003] 一致：判卷、记忆、选题都锚定 KnowledgeItem。
