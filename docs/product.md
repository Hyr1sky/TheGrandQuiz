# 产品定义

Status: current

## 一句话

正考级是一个 local-first 的私人考官：它把用户认可的材料变成可追溯知识，通过有证据的追问暴露薄弱点，
并让下一轮考核优先回到这些薄弱点。

## 用户与问题

第一用户是需要长期学习技术材料、准备考试或面试的个人。用户面对的问题不是“缺少一篇总结”，而是：

- 读过不等于能回答，似懂非懂很难被主动发现；
- 答错后往往只记住一道题，没有把错误锚定到知识与原文；
- 普通聊天工具不保留可解释的学习状态，下一次又从零开始；
- 模型判断可能出错，需要 Evidence、trace 和可纠正的数据闭环。

## 核心循环

```text
导入并审批材料
→ 建立 KnowledgeItem 与 exact Evidence
→ 围绕当前材料对话或逐题考核
→ 代码根据判决更新薄弱状态
→ 下一轮优先复考
→ 用户纠正产生可复用的评测信号
```

产品的最小价值单位不是“生成了一段回答”，而是一次能够回到材料、解释判决并影响后续学习的考核。

## 产品原则

1. **考核优先**：阅读、对话、统计和图谱都服务于发现与修复知识缺口。
2. **Evidence first**：知识、题目、判决和纠正必须能追溯到明确材料或用户输入。
3. **LLM 判断，代码记账**：语义判断可以由模型完成，状态转移和持久化后果必须确定。
4. **Local-first**：本地单用户是当前安全边界；外部模型调用必须显式配置。
5. **可纠正而非假装确定**：模型分类和诊断保留来源、置信度与审核状态。
6. **先证明消费者再增加结构**：没有选题、检索或学习收益证据时，不提前建设知识图谱或复杂分数。

## 当前版本边界

v0.4 在 v0.3 的证据闭环上补齐两个人工授权面：用户可以先搜索并审核材料候选，只有批准后才进入既有
Acquisition；判决纠正与人工盲标先进入本地 Eval inbox，只有完成隐私审核的活跃候选才能组成不可变数据集
快照。发现不会自动抓取或写入知识库，反馈不会自动上传、训练或打开发布 gate。

真实盲标样本仍在积累，尚未达到判卷 calibration gate，因此自适应选题、自动 Demand Judge、错因晋升和
能力蓝图仍不启用。账号、多用户、云同步、公网托管、主动复习排期、ASR 数字人、完整资源管理和知识图谱
也不属于当前承诺。

## 下一阶段要证明什么

下一步是继续收集 10–30 条真实人工盲标样本，通过 v0.4 inbox 审核并固定成快照，再测量 verdict 一致率、
逐点评判准确率、严重误判、重试与 Token 成本。用户纠正继续只作为非盲标探索样本。只有质量证据通过后，
才决定哪些信号可以进入后续学习策略；v0.4 本身不新增自动策略。

具体实体与候选字段见 [领域模型](domain-model.md)，执行顺序见 [路线图](roadmap.md)。
