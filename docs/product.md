# 产品定义

Status: current

## 一句话

正考级是一个 local-first 的私人考官：它把用户认可的材料变成可追溯知识，通过有证据的追问暴露薄弱点，
并让下一轮考核优先回到这些薄弱点。

## 用户与问题

第一用户是需要长期学习技术材料、准备考试或面试的个人。用户面对的问题不是“缺少一篇总结”，而是：

- 读过不等于能回答，似懂非懂很难被主动发现；
- 答错后往往只记住一道题，没有把错误锚定到知识与原文；
- 普通聊天工具不保留可解释的学习状态，下一次又从零开始；
- 模型判断可能出错，需要 Evidence、trace 和可纠正的数据闭环。

## 核心循环

```text
导入并审批材料
→ 建立 KnowledgeItem 与 exact Evidence
→ 围绕当前材料对话或逐题考核
→ 代码根据判决更新薄弱状态
→ 下一轮优先复考
→ 用户纠正产生可复用的评测信号
```

产品的最小价值单位不是“生成了一段回答”，而是一次能够回到材料、解释判决并影响后续学习的考核。

## 产品原则

1. **考核优先**：阅读、对话、统计和图谱都服务于发现与修复知识缺口。
2. **Evidence first**：知识、题目、判决和纠正必须能追溯到明确材料或用户输入。
3. **LLM 判断，代码记账**：语义判断可以由模型完成，状态转移和持久化后果必须确定。
4. **Local-first**：本地单用户是当前安全边界；外部模型调用必须显式配置。
5. **可纠正而非假装确定**：模型分类和诊断保留来源、置信度与审核状态。
6. **先证明消费者再增加结构**：没有选题、检索或学习收益证据时，不提前建设知识图谱或复杂分数。

## 当前版本边界

v0.4 在 v0.3 的证据闭环上补齐两个人工授权面：用户可以先搜索并审核材料候选，只有批准后才进入既有
Acquisition；判决纠正与人工盲标先进入本地 Eval inbox，只有完成隐私审核的活跃候选才能组成不可变数据集
快照。发现不会自动抓取或写入知识库，反馈不会自动上传、训练或打开发布 gate。

首批真实盲标已形成：20 条独立答卷完成 owner 终审，19 条经本地隐私审核进入不可变 Dataset Snapshot，
1 条因 rubric overconstraint 排除。第一次生产 Grader calibration 未通过后，报告审计、Provider thinking
方言和“模型逐点评级、代码三值聚合”契约已经补齐；同一开发集上的 2×2 pilot 显示
`deepseek-v4-pro + thinking off` 是当前质量/成本/延迟最均衡的候选，但 10 条已见开发样本不足以改变生产
默认或打开质量门。自适应选题、自动 Demand Judge、错因晋升和能力蓝图仍不启用。账号、多用户、云同步、
公网托管、主动复习排期、实时 ASR 数字人、完整资源管理和知识图谱也不属于当前承诺。

## 判卷质量路线（继续受 Eval gate 限制）

Required Claims 与隐藏聚焦复核均未稳定优于 flat atomic ExpectedPoint，因此新题和默认判卷已回到
`ExpectedPoint + AnswerEvidenceUnit ID + 代码三值聚合` 基座。下一阶段不立即消耗新的 holdout，而是先在
Development Gold 证明“系统能否识别真正需要向学习者澄清的模糊点”。澄清必须是一次用户可见的补充回答，
而不是第二个隐藏 Judge；仍不确定时不强行记账。当前生产报告中没有可用的 `uncertain` 信号，所以该能力
仍受原型 gate 阻挡。首个二分类原型进一步证明 grading matched/missing 不能替代 Interaction Gold：
“直接支持但初判冲突 / 已有歧义表达 / 确实没有支持”必须分开。只有候选在已揭盲数据上提高确定判卷质量、控制 serious error 与成本，才冻结实现并
收集新的 unseen human holdout。三态真实原型随后虽识别 4/4 直接支持，却识别 0/2 歧义且未过结构、
成本和 exact 门，因此自动澄清仍关闭。当前已交付更保守的用户主动申诉：开放题允许一次补充、同 rubric
重判并追加式纠正；它不把未通过的自动分类器包装成产品能力。

具体实体与候选字段见 [领域模型](domain-model.md)，执行顺序见 [路线图](roadmap.md)。

## v0.4.0 发布边界

v0.4.0 可以作为 local-first 早期版本发布，因为材料发现、人工授权、数据审核、判决纠正和用户申诉都具有
确定性的代码边界与回归测试。它不宣称模型判卷已经达到无人值守质量：最近一次 30 条真人 Development
Gold 的正式实验中，合法输出率与逐点评判准确率达标，但三值一致率为 83.33%，低于预注册的 85%。该结果
阻止的是自动策略晋升，不阻止把“可审计、可人工纠正”的软件能力交给小范围用户试用。

## v0.5.0 发布边界：Voice Interview

v0.5 不从“做一个数字人”开始，而是先验证口头作答是否能可靠进入现有考核循环。桌面 Web 用户录完一段语音后，
系统调用外部 ASR 生成可编辑草稿；用户确认或修改后，才以 `input_modality=voice` 进入原有判卷、申诉和薄弱记账。
获批材料会产生一个可重建的小型语音识别词表，并在当前题目范围内收窄，以改善 ReAct、AgentEvent 等专业词。

本阶段的价值是口头表达练习和未来模拟面试基建。它不承诺实时字幕、TTS 播题、自然打断、实时双工考官、形象
数字人或多设备兼容，也不会把 ASR 草稿自动当成用户答案。详细边界见
[v0.5 Voice Interview 设计契约](design/v050-voice-interview.md)。
