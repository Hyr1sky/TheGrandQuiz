# TheGrandQuiz v0.4.0

> Release candidate notes. 创建 `v0.4.0` GitHub Release 时使用同一份内容；tag、Release 与 PyPI
> 仍是仓库所有者单独批准的发布动作。

正考级（TheGrandQuiz）是一个考核驱动、local-first 的个人学习 Agent。v0.4.0 把 v0.3 的证据反馈闭环
和 v0.4 的人工授权闭环一起交付：系统不只会导入材料、对话和考核，也能让用户控制候选材料与 Eval 数据
何时进入可信路径，并在开放题判卷有争议时补充一次说明。

## Highlights

### 人工授权的材料发现

- Web 可以按主题搜索持久候选；搜索阶段不抓正文、不调用 Reader、不写知识库；
- 每个候选保留 provider 顺序、规范 URL、质量标记和审核状态；
- 批准后复用既有 Acquisition 状态机、SSRF/质量边界和知识点二次审批；
- request id、control token、activation outbox 与 SQLite CAS 避免重试或多进程重复启动。

### 可审核的 Eval 数据闭环

- 判决纠正和人工盲标先进入本地 Eval inbox，不自动上传或训练；
- 敏感正文默认折叠，只有 active + approved 候选可以组成不可变 Dataset Snapshot；
- `unassisted_human / assisted_human / model / synthetic_oracle` 来源身份进入编译与报告；
- release-eligible 与 exploratory 样本强制分列，已见开发集不能冒充新的 Holdout。

### 更可靠、可纠正的开放题判卷

- 新题默认使用 flat atomic `ExpectedPoint`；LLM 逐点判断，代码按预注册核心点评合三值；
- 学习者答案由代码切成稳定 `AnswerEvidenceUnit`，模型只选择 ID，不能复制、改写或省略原文；
- Record/Replay 支持同一请求的有序响应序列，同时继续读取旧单响应 cassette；
- Web 开放题支持一次用户主动申诉：原答案保持不可变，补充说明按同一 `QuestionSpec` 重判，最终状态通过
  append-only Verdict Correction 与 reconciliation 修正；
- 自动 ambiguity classifier、Required Claims 默认路线和隐藏聚焦复核均因真实实验未过门而保持关闭。

### Provider 与审计能力

- DeepSeek / DashScope 的 API dialect、thinking mode 与 reasoning effort 显式分离；
- Calibration Report 分开报告合法输出率、语义质量、来源身份、重试与 Token；
- CLI 与 Web 继续复用同一 AssessmentPlan、QuestionSpec、LearningFact Journal 和事件脊柱；
- v0.2.0 schema v15 数据可由 v0.4.0 自动升级到 schema v16，资源、KnowledgeItem、Evidence 与学习状态保留。

## 安装

需要 Python 3.12+。推荐使用 [uv](https://docs.astral.sh/uv/)：

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python ./grandquiz-0.4.0-py3-none-any.whl
.venv/bin/grandquiz --help
.venv/bin/grandquiz report --out ./eval-report
.venv/bin/grandquiz-web
```

浏览器打开 `http://127.0.0.1:8000`。真实模型调用前，从 `.env.example` 创建 `.env`，分别配置 basic 与
enrich 两个 OpenAI-compatible 角色。示例模型只是安全起点，实际模型名称、价格与可用性以供应商为准。

## 升级与数据安全

升级前先停止 CLI/Web 并备份 `~/.grandquiz`。v0.4.0 会把 v0.2.0 的 learning schema v15 顺序迁移到
v16；迁移只新增人工授权 inbox/outbox 表。自动兼容测试覆盖旧资源、知识点、Evidence 和薄弱状态的读取。
不要用旧版本打开已经迁移且继续写入的数据副本。

真实 LLM 调用会把 system prompt、用户消息、题目、评分点、选定材料 Evidence 和必要上下文发送给 `.env`
配置的服务。不要导入或评测无权发送给该供应商的内容，也不要公开 `.env`、数据库或完整 trace。

## 质量边界与已知限制

- 本版本可以发布的是“可审计、可纠正”的软件闭环，不是无人监督判卷质量承诺；
- 最近一次 30 条真人 Development Gold 实验为 100% 合法输出、90.83% 逐点准确率、83.33% 三值一致率，
  后者低于预注册 85% 门槛；该数据已揭盲，不能继续调到通过后充当 release holdout；
- 模型可能对同义表达、组合表达和合理替代方案产生 false negative；请结合逐点评判、Evidence、一次申诉
  与 trace 使用，不要把结果当作高风险考试的最终裁定；
- 单用户、本机优先；没有账号、鉴权、云同步或公网部署承诺；
- Web 尚无完整的资源删除、revision/知识点维护、学习统计和批量入库；
- 自动材料批准、定时发现、自动 Eval 晋升、自适应学习策略、知识关系和 ASR 均未启用；
- Windows 尚未完成人工验收；Runtime 内部 API 不承诺第三方 SDK 的 semver 稳定性。
