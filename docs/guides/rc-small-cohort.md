# v0.5.0 小范围测试指南

## 目的

RC 测试不是收集“喜欢/不喜欢”，而是回答三个问题：

1. 陌生技术用户能否只看 README 完成首次闭环；
2. 出错后是否能凭错误信息和 trace_id 解释与恢复；
3. 用户第二天是否愿意继续使用。

第一轮招募 3–5 人，持续 7–14 天。只修 P0/P1、安装阻断和明显契约回归，不在 RC 中增加新功能。

## 安全准备

- 使用 Release 提供的 wheel，不共享维护者的开发目录；
- 使用独立 `.env` 和测试供应商 key，设置可接受的额度；
- 若通过 OpenRouter BYOK 发放临时 key：为每位测试者创建独立、限额、可过期的 key；在两个 BYOK
  provider 上开启 `Always use for this provider`，并设置
  `LLM_ONLY_PROVIDER=deepseek` / `ENRICH_LLM_ONLY_PROVIDER=alibaba`，使上游失败时直接报错而不走
  OpenRouter 共享端点；
- 给临时 key 单独分配 Guardrail，只允许本次 RC 使用的两个模型与两个 provider；不要修改整个
  workspace 的默认 Guardrail，以免影响维护者自己的其他 key；
- 优先使用公开文档或测试者有权发送给 LLM 的非敏感材料；
- 测试前备份 `~/.grandquiz`，或使用没有生产数据的新设备/账户；
- 不把 Local Web 暴露到局域网或公网；
- 反馈时不上传 `.env`、数据库、私人正文或完整模型上下文。

## 固定场景

### A. 安装与首次价值

1. 从 RC wheel 建立干净 Python 3.12 环境；
2. 运行 `grandquiz --help`；
3. 运行离线 `grandquiz report`，确认 17/17；
4. 复制 `.env.example` 并配置 basic/enrich 两个角色；
5. ingest 一份本地 Markdown/Text，人工剔除至少一个候选 KnowledgeItem；
6. 在 Web 选择材料，提出一个要求引用原文的问题；
7. 点击 citation，确认 quote 与 section_path 可理解。
8. 不看维护者演示，使用首次指南或 Chat 空状态示例找到考核与运行观测入口。

记录：

- 安装到首次有效回答的分钟数；
- 是否需要 README 之外的口头帮助；
- 最困惑的一个术语或步骤。

### B. 考核与恢复

1. 完成至少三题，包含一次 Evidence reveal；
2. 至少产生一个薄弱或观察中状态；
3. 中途取消一轮考核，确认 Observatory 不再显示运行中；
4. 重启 `grandquiz-web`；
5. 再次考核，检查薄弱状态、题目去重与历史 trace；
6. 导出一个 trace HTML。
7. 在一道开放题判决后提交一次补充说明，确认原回答不被覆盖、最终判决与学习状态同步修正。

### C. 人工授权的数据闭环

1. 在 Web 中按主题搜索一批材料候选，确认搜索完成时知识库没有新增资源；
2. 拒绝一个候选，再批准另一个候选，确认只有批准项进入既有 Acquisition 与知识点二次审批；
3. 打开 Eval 数据管理，确认判决纠正固定标为 exploratory；
4. 导入一条明确 `blind_to_model_output=true` 的人工标签，展开检查敏感字段后批准；
5. 生成 Dataset Snapshot，确认 eligible 与 exploratory 数量分列，并在重启后仍可读取。

记录：

- Evidence 是否真的帮助回忆，而不是直接泄露答案；
- 判决是否能由材料解释；
- 重启后是否出现重复记账或状态丢失。

### D. 边界行为

1. 连续点击提交/下一题；
2. Chat turn 运行中点击“停止生成”，确认停止后能继续发送；再验证运行中不能并发发送；
3. 在考核中要求 Chat 打开文章；
4. 尝试一份包含远程图片、宽表格或代码块的 Markdown；
5. 使用一个低质量/登录页 URL，确认不会污染 KB。

任何挂起、数据损坏、安全边界绕过或无法解释的 scope 变化都按 P1 处理。

### E. 可选语音答题

仅在测试者自行配置 DashScope Key、使用桌面 Chromium 且明确同意发送录音时执行：

1. 在开放题录制一段包含材料术语的回答，结束后确认麦克风已释放；
2. 等待可编辑转写草稿，先回放录音，再修正一个识别词并提交；
3. 确认最终判卷只使用编辑后的答案，Trace 不出现音频、草稿正文或词表正文；
4. 录制第二段回答并在上传/识别期间取消，确认不会迟到恢复或生成正式答案；
5. 在设置中关闭材料词表，确认新 VoiceRun 才采用新策略。

## 分级

- P0：密钥/私人数据泄漏、不可恢复的数据破坏；
- P1：核心安装/ingest/Chat/考核不可用，scope 污染，运行永久悬挂；
- P2：有 workaround 的契约或体验缺陷；
- P3：文案、视觉细节或未来能力建议。

P0/P1 阻止正式发布；P2 必须有明确取舍或进入已知问题；P3 进入发布后 backlog。

## 退出标准

- 3–5 人中的大多数无需维护者远程操作即可完成首次闭环；
- 没有未解决 P0/P1；
- 所有失败都有稳定错误或可审计 trace；
- 安装问题不依赖“在仓库目录运行”才能解决；
- 反馈主要转为体验优化，而不是核心流程无法完成；
- 测试者能准确复述哪些数据会发送给外部 LLM；
- 至少一半测试者明确表示第二天愿意继续使用。
