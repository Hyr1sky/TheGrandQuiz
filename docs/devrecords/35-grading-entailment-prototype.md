# 35. 判卷语义蕴含原型：为什么没有继续堆 Prompt

日期：2026-08-04

## 这一步想修什么

Holdout 03 的正式 release gate 只差一个样本，但五个改变三值结论的错误都属于同一类：
学习者没有复述参考答案的术语，却用组合步骤、同义机制或不同组件名表达了相同意思，模型把它们
判成了 `missing`。

这看起来像一句“允许同义表达”就能修，但生产 Prompt 本来已经有这条规则。贸然再加一句，可能
修回漏判的同时把真正缺条件的回答放过去。因此本轮先用已经揭盲的 12 条 Development Gold 做
一次可证伪原型，不直接修改生产代码。

## 怎么试的

固定基线是 7/12 三值一致、37/48 逐点正确、19,512 Tokens。成功条件在调用模型前写死：

- 至少修回原来 5 个三值分歧中的 4 个；
- 不能新增任何逐点评判错误；
- 12/12 输出合法，严重假阴性/假阳性仍为 0；
- Token 增幅不超过 15%。

随后依次测试四种思路：

1. 判 `missing` 前显式复核同义词、步骤组合和等价机制；
2. 在复核上增加正反例边界；
3. 先拆必要子条件，所有子条件齐全才命中；
4. 不增加规则，只移除非权威的完整参考答案，让模型只看原子 rubric 和 Evidence。

所有调用都使用相同的 `deepseek-v4-pro / Thinking Off`，报告和 cassette 保存在 gitignored 的
`localtemp/calibration/grading-entailment-prototype-01/`，可离线审计。

## 结果

| 方案 | 三值一致 | 逐点正确 | Tokens | 新错误 |
| --- | ---: | ---: | ---: | ---: |
| 基线 | 7/12 | 37/48 | 19,512 | — |
| 联合蕴含复核 | 9/12 | 39/48 | 21,922 | 4 |
| 对照护栏 | 9/12 | 41/48 | 22,613 | 4 |
| 必要子条件 | 8/12 | 39/48 | 21,465 | 1 |
| 仅原子 rubric | 8/12 | 37/48 | 18,699 | 4 |

没有一个方案同时满足召回率和精确率。把已有四组判定做所有可能的离线投票组合，也找不到“修回
至少 4/5 且零新增错误”的规则。因此本轮没有为了让数字变绿而修改阈值、标签或生产 Prompt。

## 通俗理解

现在一个 `ExpectedPoint.description` 同时承担了两件事：给人解释“这个点是什么”，又让模型自己
猜“这句话里到底有几个必须满足的小条件”。Prompt 放宽时，模型更会联想，但容易把只答一半的内容
脑补完整；Prompt 收紧时，脑补少了，又会要求术语或示例实现过于相似。

所以真正缺的不是更多判卷说明，而是更清楚的数据：每个评分点保留一段人类可读说明，再附一组
原子的 `required claims`。代码明确规定这些 claim 是 `all-of`，模型只负责判断学习者 Evidence 是否
逐项支持。这样“允许多句话组合”与“少一个条件仍不算命中”可以同时成立。

## 下一步与边界

下一步候选 seam 是 `QuestionSpec(ExpectedPoint)` → `grade_answer`：

- 新题生成结构化的原子 required claims；
- 旧题没有新字段时回退到现有 description，保证数据可读；
- Grader 只按 claim 判定，参考答案留给反馈展示，不再充当隐性 rubric；
- 通过生产公开入口做 TDD，并在新题/新答卷上建立新的 unseen holdout。

本轮数据已经揭盲，只能帮助开发，永远不能被重新命名为 release holdout。修复完成后仍需新的人类
盲标集才能重新打开自动判卷发布门。
